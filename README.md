### Задание 3
Модуль - 3.collection
> В рамках данной работы необходимо разработать (на языке Java) программный код, реализующий структуру данных (коллекцию) со следующими особенностями:
>
> 1. Хранит множество значений одного типа (тип может быть конкретный, но желательно обобщённый).
>
> 2. Все значения в данном наборе гарантированно отсортированы (с использованием внешнего компаратора или на основе метода сравнения самих объектов).
>
> 3. Значения можно:
>
>   3.1. Получать по индексу.
>
>   3.2. Проверять наличие или отсутствие определённого значения.
>
>   3.3. Получать индекс местонахождения значения в коллекции (если значение в ней присутствует).
>
>   3.4. Удалять значение по индексу.
>
>   3.5. Добавлять значение в коллекцию. Так как коллекция отсортирована, добавление по индексу недопустимо.
>
> 4. Операции должны иметь следующую сложность:
>
> 4.1. Получение значения по его индексу: O(1).
>
> 4.2. Поиск значения: O(log n).
>
> 4.3. Добавление значения: О(n).
>
> 5. Прочие методы могут быть добавлены по необходимости.

### Задание 12

Модуль - 12.consoleapp

#### Постановĸа задачи
> Описание задания
> 
> Нужно реализовать одно небольшое консольное приложение.
> 
> Цель — закрепить понимание трёх паттернов: Template Method, Chain of Responsibility, Visitor.
> 
> Логика упрощённая, никакой сложной архитектуры.
> 
> Все результаты выводятся в консоль.
> 
> Приложение моделирует обработку заказа в интернет-магазине:
> 
> заказ проходит проверки, затем оформляется, а список товаров обрабатывается двумя разными посетителями.
> 
> Требования к реализации
> 1. Template Method
>    Необходимо создать базовый алгоритм оформления заказа:
> 
> processOrder():
> 1. validate()         // абстрактный метод
> 2. calculatePrice()   // абстрактный метод
> 3. pay()              // абстрактный метод
> 4. notification()     // обычный метод, может быть переопределён
> processOrder() должен быть финальным или недоступным для изменения.
> 
> Два конкретных варианта оформления:
> 
> DigitalOrderProcessor
> 
> Проверка: есть email.
> 
> Расчёт: только цена товара.
> 
> Оплата: онлайн.
> 
> PhysicalOrderProcessor
> 
> Проверка: есть адрес доставки.
> 
> Расчёт: цена товара + доставка.
> 
> Оплата: при получении.
> 
> Вывод в консоль — краткие сообщения о шагах.
> 
> 2. Chain of Responsibility
>    Нужно реализовать предварительные проверки заказа перед выполнением processOrder().
> 
> Базовый обработчик:
> 
> Handler:
> next
> handle(order):
> если check(order) -> next.handle(order)
> иначе -> остановить цепочку и вывести ошибку
> check(order)  // абстрактный
> Три конкретные проверки:
> 
> CheckStockHandler — товар в наличии.
> CheckBalanceHandler — достаточно средств.
> CheckFraudHandler — не выглядит подозрительным.
> Цепочка:
> 
> CheckStock -> CheckBalance -> CheckFraud
> Каждый шаг выводит в консоль, прошёл заказ проверку или нет.
> 
> 3. Visitor
>    Нужно реализовать обработку списка товаров заказа двумя разными посетителями.
> 
> Типы товаров:
> 
> Book
> VideoGame
> Laptop
> Каждый тип должен реализовать метод:
> 
> accept(visitor)
> Интерфейс посетителя:
> 
> Visitor:
> visitBook(Book)
> visitVideoGame(VideoGame)
> visitLaptop(Laptop)
> Два посетителя:
> 
> PriceVisitor — подсчёт общей стоимости товаров.
> ReportVisitor — формирование текстового отчёта (вывод в консоль).
> Итог
> В одном консольном приложении должны быть реализованы:
> 
> алгоритм обработки заказа (Template Method);
> цепочка проверок заказа (Chain of Responsibility);
> обработка товаров через посетителей (Visitor).
